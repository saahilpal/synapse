# ADR 0009: Projection-First User Interface Architecture

## Context

Synapse stores a large volume of historical cognition facts, event logs, and dependency relationships. Querying these raw database tables directly from the front-end causes performance bottlenecks, exposes system implementation details, and increases cognitive load on the user.

## Decision

We implement a bounded, projection-first API layer. The visual cognition UI is prohibited from querying raw internal SQLite tables directly. Instead, all graph slices and timelines are loaded as pre-computed or on-demand cached projections generated by the `ProjectionEngine` class.

Projections are scoped strictly by `context_hash` and categorized by visual intent:
- `overview`: A high-level system mapping filtering out low-level code modules.
- `subsystem`: A detailed slice focused on module components matching a folder path prefix.
- `replay`: A visual representation of the context commit DAG history.
- `drift`: Visualizes which code modules have modified file hashes relative to the cognition model.
- `assumption`: Focused validation maps for assumptions and constraints.
- `incident`: Slices showing recent incident markers and affected components.
- `branch`: Side-by-side branch comparison diff graphs.

## Consequences

- The user interface is decoupled from storage schemas.
- Large repositories remain fast to browse, as projections are clamped to a configurable maximum node count (default: 150) and cached in SQLite under a `projection_cache` table.
- Reduces token and processing footprint by performing heavy filtering on the host backend rather than the browser client.
