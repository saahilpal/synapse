# Synapse Skills Matrix

Synapse requires a broad but disciplined skill set. The project should use these skills to improve cognitive efficiency, not to add unnecessary infrastructure.

## Skill Matrix

| Skill | Why it matters | Where it applies | Best practices | Anti-patterns | Implementation guidance | Debugging guidance | Scaling concerns |
|---|---|---|---|---|---|---|---|
| Systems engineering | Keeps the runtime coherent across storage, Git, parsing, APIs, and agents. | Cross-module architecture, invariants, release planning. | Define boundaries, failure modes, and operational budgets. | Letting every subsystem invent its own truth model. | Write contracts before adapters and keep source-of-truth paths explicit. | Trace a fact from source to event to object to projection. | Scale by simplifying invariants before adding infrastructure. |
| Runtime architecture | Determines how the daemon starts, stops, recovers, and serves live context. | Daemon, workers, queues, scheduler, replay. | Separate lifecycle orchestration from domain logic. | Long-running tasks inside CLI handlers or Git hooks. | Use a small process supervisor inside the daemon and cancel-safe workers. | Inspect runtime mode, queue depth, worker state, and active context hash. | Add process boundaries only when single-process limits are measured. |
| Event-driven systems | Makes cognition replayable and auditable. | Event store, background jobs, projection updates. | Use idempotent handlers, stable event names, and schema versions. | Mutable events or event handlers with hidden side effects. | Persist the event before derived projections and record processing outcomes. | Replay a short event range and compare state hashes. | Use compaction and snapshots without rewriting event history. |
| Async programming | Keeps local UI and APIs responsive during indexing. | asyncio queues, FastAPI, workers, scheduling. | Bound queues, avoid blocking calls, isolate CPU-heavy work. | Running parsers or embeddings on the event loop. | Use async service APIs and executor pools for CPU-bound work. | Check blocked loop warnings, stuck tasks, and queue starvation. | Partition priority lanes for interactive and background work. |
| Cognitive systems | Defines how meaning becomes durable memory. | Extraction, relevance, confidence, drift, compression. | Promote facts only with provenance, trust, and validity. | Treating summaries as truth without evidence. | Model facts, assumptions, decisions, risks, and relationships explicitly. | Ask why a fact is active and inspect evidence chain. | Bound cognition through relevance and decay rather than larger prompts. |
| AI memory systems | Prevents memory from becoming chat-log storage. | Hot/warm/cold memory, vector recall, graph memory. | Separate truth, retrieval, summaries, and caches. | Raw transcript hoarding or vector-only truth. | Store semantic units with confidence and validity metadata. | Compare retrieved memory against context object and provenance. | Use tiers, filters, and compression before adding capacity. |
| Graph systems | Captures structural relationships and impact. | Graph memory, dependency maps, decision links. | Use stable IDs, typed edges, and temporal validity. | Static graphs with no time semantics. | Apply graph deltas from context objects and keep the graph rebuildable. | Inspect node identity, edge validity, and source evidence. | Move from NetworkX to Neo4j only after query and size limits are real. |
| Vector systems | Enables semantic recall across durable cognition. | Qdrant, embedding workers, memory search. | Use metadata filters and version embedding models. | Embedding everything or returning expired facts. | Embed stable semantic objects, not arbitrary lines. | Check vector payload context hash, trust, validity, and model version. | Partition collections by model/schema and batch writes. |
| Semantic retrieval | Delivers relevant context to agents cheaply. | MCP resources, search APIs, planning support. | Combine vector search, graph filters, and provenance-aware reranking. | Returning top-k similarity as final truth. | Retrieve summaries first, then evidence on demand. | Inspect query filters, scores, rerank rationale, and omitted facts. | Keep result windows small and context-head scoped. |
| Git internals | Makes cognition synchronize with real repository evolution. | Commit linkage, branches, rollback, rebase handling. | Understand refs, commits, worktrees, merge bases, and reflogs. | Equating timestamps with Git lineage. | Use GitPython for metadata and keep hooks lightweight. | Compare Git HEAD, branch ref, merge base, and context head. | Avoid full history walks; process commit ranges lazily. |
| Parser engineering | Turns source files into meaningful structure safely. | Markdown, Tree-sitter, manifests, config files. | Parse incrementally and handle malformed input. | Regex-only parsing for language structure. | Build parser adapters with stable semantic output schemas. | Save parser diagnostics and source spans. | Cache parse trees and skip generated or oversized files. |
| AST processing | Extracts imports, symbols, dependencies, and ownership signals. | Code cognition and graph deltas. | Normalize AST output into language-neutral entities. | Binding core cognition to one language grammar. | Use visitors that emit typed observations with spans. | Reproduce extraction from a fixture and compare entity IDs. | Add language-specific extractors behind common contracts. |
| Tree-sitter | Provides fast, incremental, multi-language parsing. | Code structure extraction. | Pin grammar versions and test real-world syntax. | Treating parse success as semantic correctness. | Wrap Tree-sitter in adapters that return Synapse observations. | Inspect syntax errors, byte offsets, and grammar availability. | Load grammars lazily and parse changed files only. |
| Distributed systems fundamentals | Informs reliability without overengineering. | Idempotency, ordering, transactions, replay, locks. | Apply local versions of durable log and projection patterns. | Adding Kafka, Kubernetes, or microservices prematurely. | Use sequence IDs, leases, retries, and atomic writes locally. | Identify which invariant failed: order, atomicity, idempotency, or visibility. | Scale concepts first, infrastructure later. |
| Concurrency | Prevents races between watchers, workers, APIs, and Git state. | Async queue, locks, projection updates. | Use scoped locks and clear ownership of writes. | Shared mutable state across workers. | Serialize writes per repository/context head and allow concurrent reads. | Inspect lock ownership, queue age, and duplicate context creation. | Shard by repository or context only when needed. |
| Observability | Makes cognition explainable to users and maintainers. | Logs, metrics, diagnostics, TUI, doctor. | Emit structured logs with correlation IDs and context hashes. | Logging raw sensitive content by default. | Use structlog and stable diagnostic event names. | Follow one correlation ID through pipeline stages. | Summarize metrics and bound log retention. |
| Security engineering | Protects local secrets and prevents tool or memory poisoning. | Trust model, permissions, MCP, sandboxing. | Enforce in code, redact by default, audit mutations. | Relying on prompt instructions as security. | Treat all external and repo content as untrusted until classified. | Reproduce the request path and check policy decisions. | Add policy files and signed clients for team mode later. |
| MCP architecture | Exposes cognition to agents safely and interoperably. | MCP tools, resources, permissions. | Keep MCP thin and runtime-owned. | Putting reasoning or storage mutation directly in tool glue. | Map MCP calls to typed runtime commands and resources. | Inspect request identity, permission scope, and runtime response hash. | Paginate resources and keep tool outputs bounded. |
| API design | Provides stable local interfaces for tools and dashboards. | FastAPI, WebSocket, CLI, MCP. | Version schemas and keep interfaces thin. | Returning internal models directly without redaction. | Define command/query DTOs at boundaries. | Compare API response to runtime state and permission scope. | Add pagination, filtering, and schema compatibility tests. |
| Schema design | Keeps events, objects, and APIs evolvable. | SQLite, msgpack objects, Pydantic models. | Version schemas and write migration tests. | Ad hoc dictionaries in durable payloads. | Use immutable Pydantic models and canonical serialization. | Validate old fixtures under new schema code. | Keep hot metadata compact and large payloads content-addressed. |
| Storage engines | Ensures durable local state is correct and repairable. | SQLite WAL, object store, Qdrant, graph projections. | Separate source-of-truth storage from derived indexes. | Treating caches as canonical. | Use transactions, atomic file writes, and integrity checks. | Run doctor checks for missing objects and projection hash mismatches. | Move to heavier backends only behind ports. |
| Performance engineering | Keeps Synapse pleasant to run all day. | Watchers, parsing, embedding, replay, queries. | Measure before optimizing and set budgets. | Embedding every line or rescanning whole repos. | Use content hashes, incremental parsing, batching, and lazy enrichment. | Profile hot paths and compare against budgets. | Bound queues and memory tiers before adding services. |
| Profiling | Finds real bottlenecks in local workloads. | Parser cost, graph updates, replay, vector writes. | Profile representative repositories and modes. | Optimizing synthetic tiny cases only. | Add `doctor` profiling hooks and benchmark fixtures. | Capture CPU, memory, IO, and event-loop stalls. | Keep profiles comparable across releases. |
| Testing | Proves correctness across replay, rollback, and trust. | Unit, integration, replay, rollback, security tests. | Test invariants and failure paths. | Only testing happy-path CLI output. | Use temporary Git repos and deterministic fixtures. | Re-run event sequences and compare context hashes. | Separate fast tests from large repository benchmarks. |
| CI/CD | Keeps the OSS project healthy. | GitHub Actions, pre-commit, releases. | Run lint, format, type, tests, and docs checks. | Publishing releases without replay compatibility tests. | Use uv in CI and pin tool versions. | Compare local and CI Python/tool versions. | Add matrix testing for OS and Python versions over time. |
| Developer tooling | Makes contribution and local operation ergonomic. | CLI, doctor, configs, pre-commit, docs. | Build commands that explain state and next steps. | Hidden setup requirements. | Keep setup scriptable with `uv sync` and diagnostics visible. | Run `synapse doctor` and inspect environment findings. | Keep defaults simple and make advanced knobs opt-in. |
| Terminal UI engineering | Gives developers a live local dashboard. | Textual dashboard. | Show state, drift, DAG, queues, and warnings clearly. | Decorative dashboards that hide operational facts. | Build read-only views first, then guarded actions. | Compare displayed state hashes to API state. | Virtualize long lists and throttle updates. |
| Software architecture | Preserves maintainability as subsystems grow. | Package layout, interfaces, docs, ADRs. | Use bounded contexts and dependency inversion. | Big central classes that know everything. | Keep runtime, cognition, storage, Git, MCP, API, and security separate. | Draw the dependency graph and remove cycles. | Add abstractions only when they protect real variation. |
| Domain modeling | Gives names to Synapse's core concepts. | ContextObject, EventRecord, GraphNode, TrustRecord. | Model domain language explicitly and immutably. | Generic "memory item" blobs for everything. | Define value objects for provenance, confidence, validity, and lineage. | Inspect whether a bug is a modeling error or adapter bug. | Evolve models through schema versions. |
| Rollback systems | Enables Git-like cognition rewind. | Context DAG, projections, CLI/MCP rollback. | Activate prior state without deleting history. | Mutating old objects or clearing indexes blindly. | Append rollback events and rebuild projections by context head. | Compare active facts before/after and verify object hashes. | Use snapshots to accelerate, not replace, replay. |
| Temporal systems | Tracks fact validity across time and branches. | Temporal memory, graph edges, drift. | Separate valid time, transaction time, and Git lineage. | Using wall-clock time as truth. | Store `valid_from`, `valid_to`, context hash, and branch metadata. | Query the same fact at two context heads. | Index validity windows and scope queries. |
| Provenance systems | Makes memory auditable and trustworthy. | Every durable fact and relation. | Record source, span, hash, actor, and extractor version. | Orphaned facts without evidence. | Carry provenance through summaries, graph edges, and vectors. | Ask "why do we believe this?" and follow references. | Store detailed evidence in objects, compact refs in indexes. |
| Trust systems | Prevents unsafe promotion of weak or malicious facts. | Security, confidence, MCP writes. | Keep trust separate from confidence. | Letting agent output inherit human trust automatically. | Attach trust records to provenance and evaluate at promotion/query time. | Inspect source trust, verification status, and policy decisions. | Add signed approvals and policy files for teams. |
| Event sourcing | Makes cognition reconstructable. | Event store, replay, context versioning. | Append facts, never patch history. | Current-state-only storage with no audit trail. | Model corrections and invalidations as new events. | Replay from genesis and compare snapshots. | Use compaction and archived payloads after verification. |
| DAG systems | Represents branching and merging cognition. | Context DAG and Git branch semantics. | Use immutable nodes and explicit multi-parent merges. | Linear history assumptions. | Store parent edges and active refs separately. | Walk lineage from active head to root and validate parents. | Use delta storage and shared objects across branches. |
| Context engineering | Designs the full information environment agents receive. | MCP resources, retrieval, summaries, prompts. | Provide scoped, current, provenance-aware context. | Prompt stuffing or unfiltered memory dumps. | Compose context from graph, vector, and temporal filters. | Inspect omitted and included facts with scores. | Bound output sizes and cache common context views. |
| Documentation engineering | Keeps architecture usable and reviewable. | All docs, ADRs, subsystem specs. | Document purpose, lifecycle, diagrams, failure modes, and tradeoffs. | Shallow docs that repeat code names. | Update docs with every public contract change. | Compare implementation behavior to documented invariants. | Use docs structure that scales by subsystem. |
| OSS maintainership | Builds a project others can trust. | Governance, issues, PRs, releases, security. | Be clear about scope, quality bar, roadmap, and contribution process. | Accepting features that violate project identity. | Use ADRs, changelog, security policy, and contribution standards. | Review whether confusion is a docs, design, or process problem. | Grow governance gradually as contributors arrive. |

## Operating Rule

When two skills point in different directions, prefer the one that protects the core invariant:

> Synapse is a local-first, Git-native, bounded cognition runtime with replayable, provenance-aware state.
